# RK3588：4K60 YUV 4:4:4 低延迟验证结论

日期：2026-09-29  
设备：Orange Pi 5 Plus / RK3588 / 16 GiB / 裸板、无风扇

## 结论

**不满足要求。**

在当前硬件和无散热条件下，RK3588 不能持续完成：

> 4K60、真 YUV 4:4:4、编码 + 模拟局域网传输 + 解码 P99 低于 50 ms

原因不是格式错误或网络丢包，而是持续满负载后温度升高、性能下降。冷机短时接近目标，不能作为通过结论。

## 最终实测

测试链路：

`4K YUV444P8 → 4 个 JPEG 4:4:4 分片 → 4×A76 CPU 编码 → UDP/IP → 模拟局域网 → RK3588 MPP 硬解 → NV24 4:4:4 重组`

| 指标 | 要求 | 5 分钟实测 | 判定 |
|---|---:|---:|:---:|
| 分辨率与格式 | 3840×2160，YUV 4:4:4 | 3840×2160，NV24 4:4:4 | 通过 |
| 持续帧率 | ≥60 fps | 52.473 fps | **失败** |
| 端到端延迟 | P99 <50 ms | P99 69.476 ms | **失败** |
| 数据正确性 | 无传输、解码错误 | 10,152,000 个 UDP 包，0 错误 | 通过 |
| 稳定性 | 无持续积压 | 累计落后 43.014 s | **失败** |

温度从 42.5°C 上升到最高 84.1°C；约 69 秒、75.8°C 时开始持续降速。其后吞吐稳定在约 50–51 fps。

## 测试边界

- 局域网为单机回环模拟：真实 UDP/IP 分包、排队和重组，`netem` 模拟 1 Gbit/s、单程 1 ms ± 0.2 ms。
- 未使用物理网卡、网线、交换机或第二台接收端，因此不代表物理局域网验收。
- 使用一张自然图像重复产生 18,000 帧。它足以证明当前配置会因温升而失败，但不构成多种真实视频内容的产品级画质测试。
- 短时 1000 帧测试为 59.997 fps、P99 43.245 ms；帧率仍低于预设的 60.000 fps 门槛，而且长测已经证明该状态不可持续。

## 其他路线结论

| 路线 | 结论 |
|---|---|
| CPU JPEG XS | 约 0.509 fps，排除 |
| H.264/H.265 硬件编码 | 仅得到 4:2:0，不符合 4:4:4 |
| RK3588 硬件 JPEG 编码 | 不接受有效的 YUV444/NV24 输入 |
| CPU JPEG 编码 + CPU 解码 | 延迟可低于 50 ms，但仅约 36 fps |
| CPU JPEG 编码 + MPP 硬解 | 已测最强路线；冷机短时接近目标，裸板持续运行失败 |

## 最终判断

**这块裸板达不到目标。** 运行约一分钟后，帧率降到 50-51 fps，端到端延迟升到 P99 69.476 ms。因此，本次验证结论是：**不通过。**
